# HR Ride Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A workout preset whose middle block makes the Bike+ motorised resistance follow a heart-rate band, with hold rules for no-pedal / no-HR and a knob-override grace period.

**Architecture:** One sanctioned write (`BikeResistanceControl.setResistance`) behind the existing sensor abstraction; a pure-Kotlin `HrResistanceController` driven from `RideSession.tick`; two optional `WorkoutStep` fields (`hrTarget`, `resistance`) so the engine, cues, overlay and Setup reuse the workout path; the HR band lives in Settings and is read live each tick.

**Tech Stack:** Kotlin, Compose (overlay + Setup), kotlinx.serialization (workout JSON), DataStore (settings), JUnit 4 + kotlinx-coroutines-test + Robolectric (existing split).

**Spec:** `docs/superpowers/specs/2026-10-26-hr-ride-design.md`

## Global Constraints

- Sonnet implements in isolated worktrees under `~/Work/pedalmate-wt/<task>`; no Gradle install/connected tasks, no adb, no CPU busy loops. Fable reviews each task.
- Unit run: `./gradlew :app:testRealDebugUnitTest` (plus `:app:testMockDebugUnitTest` for Tasks 2 and 9). Copy any `TEST-*RideServiceTest.xml` before a rerun (bead 7ft flake).
- TDD: red test, run, green, run, commit. Commit messages end with the session attribution lines.
- Hold rules are verbatim from the spec: a command never goes out while the bike is not connected, HR is missing or older than 30 s, or cadence is under 30 rpm (entry commands of a `resistance` step exempt from the HR and cadence rules only). At most one AUTO change per 20 s, at most 2 units per change, AUTO clamp 10..70. A `setResistance` that returns false never moves the baseline.
- Constants live in `HrResistanceController.Companion` with these names and values: `ADJUST_INTERVAL_MS = 20_000L`, `SETTLE_MS = 3_000L`, `HR_MAX_AGE_MS = 30_000L`, `HOLD_RESET_MS = 10_000L`, `GRACE_MS = 75_000L`, `CADENCE_FLOOR = 30`, `OVERRIDE_DELTA = 2`, `AUTO_MIN = 10`, `AUTO_MAX = 70`, `BIG_ERROR_BPM = 10`, `RETRY_MS = 2_000L`.
- No per-adjustment sound, toast, or vibration. No manifest change. `PedalMate.md` read-only paragraph is updated in Task 1, not silently contradicted.
- Spike (Task 0) is gated on the bike being attached and is run by the main session, never by Sonnet. Everything after Task 1 may be built before the spike runs, but nothing merges to `phase-a` until the spike passes.

## Review Focus

1. **Bursty HR straddling the 30 s window:** HR frame at t=0, next at t=35 s. Expect: HOLD_NO_HR from t=30 to t=35, no timer reset (hold < 10 s), then AUTO resumes with the new reading. Test in Task 5 (`hr older than 30 s holds, 25 s does not` + `a 5 s hold leaves the adjust timer alone`).
2. **Knob turned during the motor settle window:** command at t=0, rider turns the knob at t=1 s so observed never reaches the commanded value. Expect: no override judgement before `SETTLE_MS`, MANUAL right after it. Test in Task 5 (`manual override is judged only after the settle window`).
3. **Workout with hrTarget but the bike cannot write** (real flavour unbound, or a future source without the capability): expect HOLD_NO_BIKE forever, overlay says `HOLD · no bike`, ride otherwise normal. Test in Task 7 (`without a resistance control the mode is HOLD_NO_BIKE and nothing is commanded`).
4. **Pause during AUTO then resume with HR now low** (rider paused, HR fell): expect no command on resume until a full 20 s has elapsed since the pause began (pause is a hold ≥ 10 s). Test in Task 5 (`a pause of 30 s resets the adjust timer`).
5. **Band edited mid-ride to exclude the current HR:** expect the next evaluation (not an immediate one) to act, HR TargetStatus to re-judge immediately (new target), and the overlay target text to change at once. Tests in Task 7 (`a live band change applies at the next evaluation without restarting the interval`) and Task 6 (`a changed band is evaluated immediately`).

**Files:**
- Create: `app/src/main/java/dev/pedalmate/workout/HrResistanceController.kt`
- Test: create `app/src/test/java/dev/pedalmate/workout/HrResistanceControllerTest.kt`

**Interfaces:**
- Produces (all in `dev.pedalmate.workout`):
  ```kotlin
  data class StepRef(val index: Int, val hrTarget: Boolean, val resistance: Int?)
  sealed interface ResistanceMode {
      data object AUTO : ResistanceMode
      data object HOLD_NO_HR : ResistanceMode
      data object HOLD_NO_CADENCE : ResistanceMode
      data object HOLD_NO_BIKE : ResistanceMode
      data object PAUSED : ResistanceMode            // ride paused, finished, or the step is neither hrTarget nor resistance
      data class MANUAL(val graceRemainingMs: Long) : ResistanceMode
  }
  data class ControlInput(
      val nowMs: Long, val running: Boolean, val step: StepRef?, val band: IntRange,
      val hrBpm: Int?, val hrAgeMs: Long?, val cadenceRpm: Int?, val observedResistance: Int?,
  )
  class HrResistanceController {
      val mode: ResistanceMode
      /** One tick. Returns a resistance to command, or null. The caller must answer every non-null return with [onCommandResult]. */
      fun update(input: ControlInput): Int?
      fun onCommandResult(delivered: Boolean)
      fun reset()
      companion object { /* constants from Global Constraints */ }
  }
  ```
  Semantics (the body is the implementer's, these are the rules): `update` returns at most one value per call and never while a command is in flight (`onCommandResult` not yet called). Delivered → `commanded = value`, `settleUntil = now + SETTLE_MS`, `lastAdjustAt = now` (AUTO only). Not delivered → nothing changes; an entry command retries no sooner than `RETRY_MS`; an AUTO command retries at the next eligible evaluation. Step change (by `index`) → per-step state reset: `baseline = null`, `pendingEntry = step.resistance`, `lastAdjustAt = now`, `commanded = null`, exit MANUAL. `baseline` is set from the first non-null `observedResistance` of the step if no command has been delivered. Override: after settle, `|observed − (commanded ?: baseline)| ≥ OVERRIDE_DELTA` → MANUAL with `graceUntil = now + GRACE_MS`; any later change of observed by ≥ 1 within MANUAL → `graceUntil = now + GRACE_MS`; at `graceUntil` → `baseline = observed`, `commanded = null`, `lastAdjustAt = now`, back to AUTO. Hold tracking: `holdSince` set on first hold tick, cleared when not holding; while `now − holdSince ≥ HOLD_RESET_MS`, `lastAdjustAt = now`. AUTO law when eligible (`now − lastAdjustAt ≥ ADJUST_INTERVAL_MS && now ≥ settleUntil && !inFlight`): error below → `+1` (`+2` if `band.first − hr ≥ BIG_ERROR_BPM`), above → `−1`/`−2`; target `= (commanded ?: baseline) ± step`, clamped `AUTO_MIN..AUTO_MAX`; inside band → nothing (and `lastAdjustAt` unchanged). Mode exposure: order of checks `!running || step == null || (!step.hrTarget && step.resistance == null)` → PAUSED; `observedResistance == null` → HOLD_NO_BIKE; for an hrTarget step: `hrBpm == null || hrAgeMs == null || hrAgeMs > HR_MAX_AGE_MS` → HOLD_NO_HR; `cadenceRpm == null || cadenceRpm < CADENCE_FLOOR` → HOLD_NO_CADENCE; MANUAL while in grace; else AUTO. A `resistance` step reports PAUSED after its entry command is delivered (nothing to show).
